# 钟楼推理台

**Clocktower Copilot** 是一个面向血染钟楼玩家的非官方、实验性记录与条件推理工具，当前聚焦「暗流涌动」7–15 人对局。用圆桌记事录入身份声称、能力信息和日夜事件，再检查它们在明确前提及有限规则模型下能否同时成立。

作者：[MrHadesZz](https://github.com/MrHadesZz) · [仓库](https://github.com/MrHadesZz/clocktower-copilot-community) · [在线试用](https://clocktower-copilot-ten.vercel.app) · [参与开发](./CONTRIBUTING.md) · [待开发方向](./docs/roadmap.md)

它使用浏览器端 Z3 规则求解，当前没有接入大语言模型。结果帮助回看条件和可能解释，不能认定玩家撒谎，也不是官方规则裁定。规则覆盖和性能仍有待完善。

## 魔典的一键分析

魔典的一键分析用法：

1. 点击座位，选择该玩家声称的开局身份。
2. 再点该座位的“记录信息”，选择能力、夜晚、目标和收到的结果；没有信息的角色只需记录身份。
3. 录入后点击底部“一键分析”。无需先勾选“准确转述”或“能力有效”。

分析临时检验已录开局身份、各阶段结束时的当前角色及准确、有效的信息能否同时成立，展示一组冲突玩家，并寻找同时放宽一人或多人的声称后能够解释全部输入的组合。每个组合携带兼容见证；点击“查看放宽的身份与信息”可以对照声称身份、该见证中的真实角色、具体报告与可能的投毒行动，点击“可能解释”查看完整分配和隐藏历史。组合已逐人恢复验证后才标记“不可再缩小”，不代表全局人数最少或唯一原因。它保留当前分支的手动前提、修订与私密视角，不会自动保存新前提。未录入的座位保持未知。

每个玩家组合还有“细查原因”：分别检验开局身份、各阶段的当前角色、每条报告的准确转述和当夜能力有效条件。结果列出可比较的具体放宽方式、座位与夜晚、原报告，以及仍保留的条件；每个解释携带兼容见证，恢复任一放宽条件都确认冲突后才标记不可再缩小。默认每次细查 20 秒、最多 6 份解释，独立提供进度、取消和证据保留。

放宽能力有效不等于已经证明能力失效。只有见证的实际角色、所见身份或时间线重放在报告的信息时点支持醉酒、中毒或角色不符时，才展示相应的可能原因；否则说明原因尚未验证。每组条件只展示一份合法见证，具体机制未穷举，也未定位固定行动事实的来源级最小解释。

冲突可能来自假跳、酒鬼、中毒或录入错误，不能直接确认为撒谎；兼容也不能证明所有人诚实。跨夜报告需要按顺序记录并确认日夜阶段完整；缺少阶段、规则不支持或超时会显示结果未知。默认分析时间预算为 30 秒，最多展示 6 组组合；达到上限、超时或检查未知时明确标记未完成。已验证结果会实时显示，取消或超时保留已有证据，关闭面板或记录变化后旧结果失效。未完成部分不会用来判断玩家。魔典顶部与结构化录入的天数选项统一为第 1–10 天。

依据 [项目 TDD](./clocktower_reasoning_copilot_TDD.md) 与 ZIP 设计包开发的本地优先网页应用。当前线上试用地址：[clocktower-copilot-ten.vercel.app](https://clocktower-copilot-ten.vercel.app)。跨阶段推理已经接入标准工作区，但 **尚未达到完整 V1 的规则与验收门槛**；具体范围见 [V1 覆盖审计](./docs/v1-coverage.md) 与 [独立规则和性能验收](./docs/v1-acceptance.md)。

## 本地运行

运行需要 Node.js 22.12+；规则测试和性能验收另外需要 Python 3。

```bash
npm install
npm run dev
```

打开终端显示的本地地址。构建和回归：

```bash
npm run build
npm test
# 独立 Python 对照与原设计包规则回归：
npm run test:rules
npx playwright install chromium
npm run test:e2e
# 对已部署站点运行同一套浏览器回归：
PLAYWRIGHT_BASE_URL=https://clocktower-copilot-ten.vercel.app npm run test:e2e
# 对已构建的预览或线上站点运行离线恢复验收：
PLAYWRIGHT_BASE_URL=https://clocktower-copilot-ten.vercel.app PLAYWRIGHT_OFFLINE=1 npx playwright test e2e/offline.spec.ts
```

`npm run build` 会打包浏览器端 Z3 Worker，并生成完整静态资源的离线缓存。生产版首次联网打开后，请等界面显示“离线资源已就绪”；之后可断网重载、恢复本地记录并运行 Z3 查询。缓存包含约 34 MB 的 Z3 WASM。开发/预览服务器与 `vercel.json` 提供所需的跨源隔离头。默认没有云端业务 API 或模型调用。

V1 性能基准：`npm run bench:v1` 测量预热 Node 查询；构建后用 `npm run bench:v1:browser` 测量浏览器冷 Worker。覆盖 10/12/15 人、2/3 夜与三档信息密度，结果带独立见证审计和预算边界。复现方式及尚未达到的门槛见 [验收记录](./docs/v1-acceptance.md)。

## 已能使用的功能

- **玩家魔典闭环：** 圆桌记事、结构化信息与行动录入、按日夜分组的历史、改口与纠正关系、阶段完整性确认、开局与阶段角色声称、前提采纳、角色查询与来源/见证展示；桌面抽屉与手机弹层共用标准对局记录。

- **八人 H0 工作区：** 快速记录、事件预览与撤回、声明和真值分离、条件分支、反例与冲突、时间线、IndexedDB 和 JSON 导出/导入。该工作区只计算设计包限定的固定角色袋与事件案例；D1处决死亡与N2已记录的死亡（或封闭的零死亡）现在通过显式夜间重放筛选隐藏行动。
- **标准 7–15 人工作区：** 独立对局、私密座位视角、来源事件、追加式撤回、分支假设、修订绑定、公开脱敏导出与私密全量恢复。初始设置和首夜信息由 Z3 查询；已封闭的白天与跨夜事件可进入有预算的隐藏行动搜索，展示见证或明确返回未知。
- **标准设置查询：** 7–15 人初始角色袋的 Z3 可能性与必然性查询，支持 Baron 配比、22 个初始真实角色、酒鬼真实角色与所见 token 分离、条件首夜报告、Spy/Recluse 逐次注册、固定红鲱鱼，以及显式首夜投毒 What-if。查询草稿随本地工作区保存并参与 JSON 导出/导入；结果展示初始分配见证，并由独立具体重放校验。
- **显式历史校验核心：** 对完整给定的真实世界，依序重放 N1、D1、N2 等阶段；处理投毒来源、僧侣/士兵保护、镇长转移、Imp/SW 继任、守鸦人/送葬者信息、处女/猎手/圣徒、提名投票、男仆主人与胜负。标准工作区会枚举未记录的隐藏行动并用这套规则检查候选；用完预算时不会把未搜索的世界当作不可能。

## 魔典内完成记录与推理

默认首页的魔典与高级工作区共享同一标准对局数据：

1. 点击玩家座位 → **记录信息**，选择能力、夜晚与报告内容。支持洗衣妇、图书管理员（含零外来者）、调查员、厨师、共情者、占卜师、送葬者与守鸦人；保存后进入魔典条件推理，查询默认指向报告者及其报告角色。
2. 分别勾选 **采纳准确转述** 和 **能力有效**。保存报告和标记角色均不会自动采纳前提。
3. 选择初始角色或最新封闭阶段的当前角色 → **运行推理**，查看结论、来源、支持见证与反例。更改命题、记录或前提后，旧结论失效，需重新运行。
4. 底部 **记录** → **记录行动或阶段结束**，用表单依次记录提名、投票（支持零票）、处决、死亡、猎手行动或胜负。投票必须对应同一天已记录的唯一提名；处决与死亡独立录入。
5. **记录** 面板按 N1、D1、N2、D2 排列。核对该阶段行动与死亡已收齐后，点击 **本阶段记录完整**，勾选确认并保存。白天确认行动与死亡，夜晚确认死亡；缺少的阶段会列在面板顶部。确认后点击 **前往D1** 或 **前往N2** 继续记录，阶段选择会随本地记录保存。未报身份和信息仍保持未知。
6. 已录声称提供 **录入纠正** 和 **玩家改口**。纠正会撤回误录、保留原文，并在当前编辑分支取消原报告的采纳；其他分支与其他前提保留。改口会关联前后声明，一键分析采用最新声明，旧报告若仍手动采纳会明确提示复核。有效投票提供 **纠正投票**，修改实际举手名单并按原投票位置重放，保存后重新核对本日完整性；**回看原投票**保留原文及旧举手名单。普通 **撤销** 保留原有来源失效提示。
7. 玩家抽屉的 **身份时点** 区分开局身份与所选阶段结束时的当前角色。例如“开局红唇女郎、N2小恶魔”可分别记录，分析会检查继任历史；阶段尚未确认完整时会返回未知。轮盘优先显示截至所选阶段最近的当前角色声称，并标注其原阶段。结构化保存能力报告只记录报告，不会覆盖开局身份。
8. 对已确认阶段补录或撤销提名、投票、处决、死亡、猎手行动，会自动重新开放该阶段，需再次核对完整性；其他阶段的确认保留。补记声称、报告或胜负不撤销已有行动与死亡的完整性确认。

所有新记录默认私密，支持本地恢复与生产版离线查询。分支可在魔典推理面板切换；落后于最新记录的分支需显式更新。通用分支创建、所见 token、额外身份与投毒假设、导入导出仍在高级工作区；冲突纠错分支可以在魔典内创建。首夜专属能力暂只接受 N1，送葬者与守鸦人报告从 N2 开始；魔典界面没有扩大引擎的规则覆盖；冲突定位支持固定事实背景下的最小前提集，见下文。

## 冲突定位与纠错

2026-10-07 新增**固定背景阶段定位**：在“记录 → 核对固定事实与阶段冲突”，或一键分析的背景冲突结果中，逐段核对完整日夜记录，回看已确认冲突阶段的原文与此前兼容见证。默认保留手动前提，也能临时只查固定事件。更早阶段未知时不称最早边界；诊断不修改记录、分支或前提，支持离线恢复。范围和证据说明见[阶段定位](./docs/design/fact-history.md)。

魔典查询返回“前提互相冲突”后：

1. 点击 **定位冲突**。系统重新确认冲突，逐项取消前提检查；可选择标准或快速预算，并可中途取消。
2. **已验证最小前提冲突集**表示该集合仍然冲突，且逐一删去任何一项都有可重放见证。它相对于固定事实记录成立，不表示条数最少、唯一原因或某个玩家一定说谎。可以展开每项的 **回看原记录** 和删除后的见证。
3. 超时、检查次数耗尽、未支持的交互或无法找到见证时，显示 **最小性未验证完成**；不能把未知当作有效删除证据。若移除全部前提仍冲突，则提示核对固定事实记录。
4. 点击 **在新分支试取消此前提**，复制当前分支及其修订，仅在新分支取消该项，自动重新查询，并展示原结果与新结果。原分支和事件历史保留，可直接返回原分支。
5. 新分支仍可能有其他冲突；可继续定位。新结果为未知时，不会宣称已经修复。分支与前提会本地保存并支持私密导出恢复；解释和结果对照属于本次查询快照，关闭面板或刷新后需重新查询。

本轮最小化对象是“采纳前提”，不是行动事实。提名、投票、处决、死亡、胜负及阶段完整性记录保持固定，并可在解释中回看。算法不通过删除死亡或完整性标记制造可行世界。改变查询、分支、记录或前提后，旧解释失效；取消或离开当前解释会终止其 Worker。

## 标准对局跨阶段录入

按发生顺序录入同一天的提名、投票和猎手行动，再显式标记记录完整。例如：

```text
1 nom 2 @D1
vote 2 = 1,3,4,5 @D1
exec 2 @D1
2 dead @D1
close actions @D1
close deaths @D1
3 dead @N2
close deaths @N2
```

首夜没有死亡；从 N2 开始，只有 `close deaths @N…` 才表示该夜没有其他死亡。处女触发的即时处决可记录提名、处决和死亡，无须虚构投票；零票可写 `vote 2 = none @D1`。已发生的胜负可写 `win good @D…` 或 `win evil @N…`。角色发言本身不是真值，需分别采纳“准确转述”和“能力有效”前提。当前跨夜可采纳共情者、占卜师、送葬者与守鸦人的能力报告，也可查询初始或最新封闭阶段的当前角色；缺少闭合记录或遇到未支持交互时会给出原因。

## 八人示例输入

```text
1 inv 4/5 poisoner @N1
2 chef 0 @N1
3 ft 7/8 no @N1
4 nom 5 @D1
vote 5 = 1,2,4,7,8 @D1
exec 5 @D1
5 dead @D1
2 dead @N2
close deaths @N2
```
