# 提名与猎手行动纠正

2026-10-08 / v0.3.0 增量。记录面板新增提名人、被提名人以及猎手行动玩家、目标的纠正。沿用追加审计记录；角色规则和未知保护保持原范围。

## 用户操作

在“记录”中找到原提名或猎手行动，也可从固定事实阶段核对的来源跳转。点击“纠正提名”或“纠正猎手行动”，核对原文并选择实际玩家。猎手行动记录只表示使用了这一行动，不认定行动者的真实角色。

纠正提名时，表单列出关联投票、可见性与全部举手玩家。选择新提名后，必须勾选“我已核对以上关联投票，同意保留举手名单并重新关联”，才能保存。更改提名人或被提名人会清除已勾选的确认，避免沿用此前核对。零票记录也需确认关联。没有投票时不生成投票，请核对是否需要补录。

保存后，当天行动和死亡的完整性确认重新开放；核对真实历史后再次确认，才能用于完整观察查询。原提名、原投票、猎手行动和每次中间替代仍可回看，发生位置不向后移动。取消或保存相同内容不改变历史。死亡与处决需分别核对；这次纠正不会代替用户修改两类结果。

例如 D1 误记“2号提名3号，1/2/3/4号举手”，后续却记录4号处决死亡。在已采纳角色与有限规则条件下，这可能冲突。用户核对后将被提名人改为4号，确认同一份举手名单，重新确认D1；示例可产生兼容见证。这不是程序推断4号一定正确，也不是认定有人撒谎。

## 审计与引用保护

`correctStandardAction` 要求活动分支已经包含最新记录，且原记录有效、位于白天并在当前视角可见。类型、发生阶段和可见性保留，所有座位经过验证。旧分支的修订和前提不变；过期表单绑定原工作区快照，记录、前提或录入阶段变化后拒绝保存。

提名纠正先检查调用者明确确认的投票ID与全部有效关联投票完全一致。若有其他视角的关联记录，则拒绝操作，不显示其私密内容。随后在内存中依次追加关联投票的撤回、原提名的撤回、新提名，以及保持名单和可见性的投票替代。所有步骤成功后才返回供界面保存的工作区；失败不会改写原工作区。

投票替代保留 `correctsEventId` 指向原投票，并引用新提名ID。验证器只允许重新关联到原提名的直接纠正替代，且举手名单必须相同。新提名出现前，原提名的所有有效投票必须已经撤回。其他提名、变化的名单、未退休原投票、错阶段或错可见性的引用被拒绝。若举手名单也录错，应另行使用投票纠正；这一操作保留既有提名关联。

观察编译沿每条纠正链找到原记录的修订位置，因此提名和计票仍占据各自原位置。提名与计票之间原本存在猎手等公开行动时，仍明确返回未支持，不能借纠正移动顺序绕过边界。

## 格式与隐私

| 纠正能力 | 工作区格式 | 含对应公开纠正的导出格式 |
| --- | --- | --- |
| 无纠正 | 2 | 1 |
| 投票名单 | 3 | 2 |
| 死亡、处决 | 4 | 3 |
| 提名、猎手行动及投票重新关联 | 5 | 4 |

新客户端继续接受工作区2/3/4。第一次使用提名或猎手纠正才升级到5，随后任何其他纠正都不会降级。旧客户端无法读取新能力时应明确拒绝；不能修改版本号伪装为旧格式。

公开导出格式由公开记录决定。私密行动及私密阶段再确认不会改变公开导出。公开提名关联私密投票时，新提名保留公开状态，替代投票与撤回保留私密状态；公开导出只包含可公开的提名原文和替代，不包含私密举手名单。原文含真实私人内容时仍需用户脱敏。
