# 角色变化、信息时点与醉毒恢复审计

更新：2026-10-03。适用于标准 7–15 人 Trouble Brewing 的有限历史模型。性能优化和基准测量继续暂缓。

## 本轮发现与修复

此前守鸦人使用整夜结束时的角色与毒效状态。两个小恶魔依次行动时，会把后来的恢复或变身带入已经触发的信息，或在后续终局时丢弃先前已经获得的信息。新增七项先写出的回归在旧实现中复现五种错误，修复后全部通过。

[守鸦人官方说明](https://wiki.bloodontheclocktower.com/Ravenkeeper)要求夜死后选择玩家并获知角色。[状态规则](https://wiki.bloodontheclocktower.com/States)区分已使用或触发的能力与持续能力：醉毒时已使用或触发的能力不会在恢复后补发。[能力规则](https://wiki.bloodontheclocktower.com/Abilities)说明，来源死亡或变身会立即结束持续效果。

现在在导致守鸦人死亡的这次小恶魔行动后，固定角色、毒效、来源与终局状态，立即结算本次信息。后续行动继续改变真实历史，不重新计算已经获得的信息。

| 情形 | 本次守鸦人信息 | 后续状态 |
| --- | --- | --- |
| 先观察投毒者，后发生自杀传位 | 仍为投毒者 | 目标可以在同夜成为小恶魔 |
| 目标先变成小恶魔，守鸦人随后死亡 | 为小恶魔 | 使用本次死亡时的真实角色 |
| 死亡时中毒，毒源随后死亡或变身 | 本次能力无效 | 夜末恢复不会补发有效信息 |
| 毒源先失效，守鸦人随后死亡 | 可以有效获得信息 | 不把较早的中毒状态延续到触发时 |
| 间谍先注册为厨师，随后成为小恶魔 | 保留当次厨师注册 | 新小恶魔的角色不会改写过去信息 |
| 目标在获知信息时中毒，随后恢复 | 当次不能特殊注册 | 后来的恢复不会改变这次注册资格 |
| 先获得信息，另一恶魔攻击后才终局 | 保留已获信息 | 终局后不新增信息 |

## 22 角色机制审计

| 角色或机制 | 当前处理与本轮结论 | 后续边界 |
| --- | --- | --- |
| 守鸦人 | 死亡时固定角色与毒效，独立核对目标及当次注册；修复了实际错误 | 其他剧本的复活、重复角色与不同死亡来源未实现 |
| 送葬者、共情者、占卜师 | 按各自后续信息步骤的健康、角色、存活及阵营处理；投毒者提前失效可恢复能力 | 继续增加更长历史与具体注册组合 |
| 僧侣 | 中毒时已作出的保护选择无效，恢复后不补发；健康保护的来源死亡立即终止 | 不作为通用多毒源循环算法 |
| 士兵 | 持续能力在恢复后立即可用，后续恶魔攻击重新检查 | 更多保护与转移组合继续扩展 |
| 投毒者、小恶魔、红唇女郎 | 每次攻击后更新毒源与角色；多恶魔、传位及实际阵营保持原模型 | 自毒仍使用已声明的单毒源有限推导 |
| 隐士、间谍 | 使用每次判定当时的真实角色与健康状态选择注册；注册不取得对应能力 | 本轮未统一穷举所有 22 角色间的注册交互 |
| 酒鬼 | 实际角色与所见镇民 token 分离；投毒结束不意味着酒鬼变为所见角色 | 模拟信息与复杂视角仍需更广审计 |
| 洗衣妇、图书管理员、调查员、厨师 | 保留首夜独立矩阵；标准 TB 当前只建模向小恶魔的角色变化 | 其他角色创建与重新触发首夜能力属于扩展边界 |
| 猎手、贞洁者、圣徒、镇长、管家、男爵 | 沿用白天动作、首次使用、终局、投票警告和设置配比；本轮不修改这些规则 | 公开事件顺序与来源解释仍需扩展 |

准确转述与能力有效继续作为分开采纳的条件；本轮不更改这套条件语义。角色、阵营、特殊注册和能力触发也分别处理，不能由某一份可能行动见证确认隐藏真相。

## 状态与证据

`NightTrace.ravenkeeperDeath` 保存本次死亡的 `speaker`、队列位置 `impActionIndex`、来源 `sourceImpSeat`、`poisonedSeat`、`poisonSourceSeat`、当时的 `roles` 与 `gameOver`。这些字段由具体行动重放生成，不保存为工作区隐藏真相。

守鸦人的报告核对读取死亡时点；后续信息读取其原有信息步骤。条件细查也读取守鸦人死亡时的毒效，即使同一份见证夜末已恢复健康，仍可支持一种死亡时中毒的解释。仅放宽能力有效不证明失效，见证没有支持时继续标记未验证。

独立 Python 模型不读取应用实现。新增矩阵核对 12/15 人、两种先后顺序、毒源死亡或变身、目标注册与角色变化、保护不补发和终局；五夜完整历史验证终局前已经获得的守鸦人信息。正常见证与篡改行动顺序、目标、缺少选择的反例，同时通过 TypeScript 和 Python 审计。

版本为首夜 v4、显式时间线 v6、观察时间线 v7、oracle v5。schemaVersion 2 不需迁移；原有时间、候选、行动预算、取消、修订和视角边界保持不变。具体测试数及复现命令见 [V1 验收](../v1-acceptance.md)。这次修复与审计仍不等于全部动态交互或完整 V1 已经验收。
