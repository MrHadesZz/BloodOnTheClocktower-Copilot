# 实际阵营、逐次注册与单毒源自毒

更新：2026-10-01。适用于标准 7–15 人 Trouble Brewing 路径，角色变化限于已实现的小恶魔和红唇女郎继任；不是任意剧本或全部 TB 交互的规范。

## 三种不同的状态

`DynamicState.roles` 表示阶段中的真实角色；`alignments` 表示玩家实际阵营；`RegistrationChoice` 只描述某一次能力判定中被视为什么。角色变化保留实际阵营，不把注册写回真实角色或阵营。[官方状态规则](https://wiki.bloodontheclocktower.com/States)明确角色和阵营独立。

初始阵营按标准角色袋初始化，此后每个日夜状态复制阵营。旧的具体状态调用可以省略 `alignments`，此时按给定角色的初始阵营初始化；这不是从变身后的角色推断过去阵营的接口。变身历史必须从初始角色袋重放。传入的阵营数组必须完整且只含 `good` / `evil`。

健康隐士可以在小恶魔自杀接任的那次判定中注册为爪牙，取得小恶魔角色并保留善良阵营。实际爪牙即便中毒也能接收健康小恶魔产生的角色变化；隐士自己的注册能力中毒时则不能使用。健康红唇女郎满足死亡前五存活条件时仍优先。这是结合[隐士](https://wiki.bloodontheclocktower.com/Recluse)、[小恶魔](https://wiki.bloodontheclocktower.com/Imp)和阵营规则的推导。

后续共情者计算死亡后的最近存活邻居，读取实际阵营并允许健康间谍/隐士的本次注册。占卜师读取恶魔角色或原先选定的善良红鲱鱼，不根据实际阵营决定玩家是否具有恶魔角色。恶魔死亡和两人存活的终局检查仍按恶魔角色、继任及存活人数运行。

## 自毒的有限模型

[投毒者官方页](https://wiki.bloodontheclocktower.com/Poisoner)允许选择任意玩家，并说明效果覆盖当夜及次日、黄昏恢复、失去来源角色后效果终止。该页没有直接列出自毒循环裁定。[寡妇官方自毒示例](https://wiki.bloodontheclocktower.com/Widow)说明自毒可以让其能力失效；这里仅参考该时序，不实现寡妇。

本项目在一个投毒者毒源的 TB 切片内采用以下**推导**：投毒者健康时的自选生效，持续保持中毒至黄昏；不因其自身能力失效而反复开关这一效果。来源死亡或取得其他角色时，效果提前结束。下一夜重新选择目标。自毒不会抵消醉酒，也不阻止其他健康角色的能力作用在其身上。这个选择不是对所有醉毒循环或跨剧本来源的完整官方裁定。

首夜 What-if、具体夜晚、跨日重放、符号查询和工作区导入共用这一范围。工作区保存行动前提和事件，仍为 schemaVersion 2；隐藏历史中的角色和阵营重新求解。固定八人 H0 教学分支保留原设计枚举，不在这次扩展内。

## 查询证据与重放

观察历史及显式行动历史的见证包含 `currentRoles`、`currentAlignments`、`currentAlive` 和具体 `timeline`。隐士接任记录唯一的 `imp_successor_n<cycle>` 爪牙注册；多恶魔夜晚另加来源座位 `_<actor>`。当前采用 `Poisoner` 表示本次合法爪牙注册，不代表其获得过投毒能力。死亡隐士触发红唇女郎的独立恶魔注册另记为 `scarlet_woman_<phase>_<observer>`，不与猎手判定共用。

重放从初始袋重新计算角色与阵营并比对证据。角色本色与实际阵营不同时必须提供阵营证据；缺项、稀疏数组、篡改和重复继任注册均被拒绝。后续共情者及占卜师验证提供的注册选择，不重新选择另一份可行注册来替代。同一个共情者数字允许多个合法组合，例如隐士注册善良、间谍注册邪恶，或隐士注册邪恶、间谍注册善良；每份具体见证都必须自身成立。

Python oracle 使用自己的集合与具体阶段模型，并审计同一份角色、行动、阵营及后续注册。它不导入应用实现。查询遇到预算上限继续返回未知；上述证明只适用于已声明的规则切片。
