# 隐士死亡、红唇女郎继任与多个恶魔

更新：2026-10-03。适用于标准 7–15 人 Trouble Brewing 的有限历史模型。性能优化与测量按用户要求暂缓。

## 规则依据和范围

健康[隐士](https://wiki.bloodontheclocktower.com/Recluse)可以在不同能力的独立判定中注册为爪牙或恶魔，死亡后也保留这一注册能力；注册不会取得被注册角色的能力。[红唇女郎](https://wiki.bloodontheclocktower.com/Scarlet_Woman)在恶魔死亡前至少五人存活时立即变成相同恶魔角色，死亡后剩四人仍符合阈值。

将两项能力组合，本模型允许隐士实际死亡时单独向健康、存活的红唇女郎注册为小恶魔，使其变成小恶魔，同时原恶魔继续存活。这是对官方角色规则的组合推导；引用页面未直接列出本项目的完整场景。注册仅影响这一次继任，死亡隐士仍为隐士，实际阵营不变，也不会触发真实小恶魔的自杀传位。

猎手指定隐士时的注册与红唇女郎判定独立：猎手判定为恶魔并杀死隐士，不强制红唇女郎也将其视为恶魔。两种继任结果均参与观察历史搜索；记录本身不会自动确认隐藏注册。

[麻脸巫婆官方说明](https://wiki.bloodontheclocktower.com/Pit-Hag)明确多个恶魔时，通常的善良胜利要求所有恶魔死亡，包括善良恶魔。本项目仅引用这条通用胜负说明，没有实现麻脸巫婆。多恶魔白天中，猎手杀死一个恶魔后可继续合法行动；仍有实际恶魔存活时不直接判善良胜利。圣徒、镇长等独立终局能力仍按原有规则检查。

## 支持的阶段

- 白天处决或猎手造成隐士死亡后，检查双方健康状态及死亡前五人阈值，允许红唇女郎继任。
- 夜晚开始时只有一个存活小恶魔，其攻击导致隐士实际死亡后，允许红唇女郎继任；继任发生在原恶魔完成此次攻击之后，本切片不追加新恶魔的当夜攻击。该时序结合[小恶魔继任流程](https://wiki.bloodontheclocktower.com/Imp)作有限推导，不声称完成通用多恶魔夜间调度。
- 保留这次夜晚的后续信息判定及下一白天，包括多个恶魔死亡与胜负观察；独立验证 N2 隐士死亡、D2 猎手杀死新恶魔并处决原恶魔的善良胜利。
- 夜晚开始时已有多个存活小恶魔，支持完整队列、各自目标、行动前死亡、来源效果终止、传位竞争与即时终局；新继任者当夜不加入队列。观察搜索仍保留预算未知，具体时序推导与证据格式见 [多恶魔夜晚](./multi-imp-nights.md)。

## 显式选择与证据

白天动作使用 `scarletRecluseRegistrations: number[]`；夜晚动作使用 `scarletRecluseRegistration: number`。省略表示本次采用隐士本色注册。记录为恶魔的座位必须在本阶段实际死亡，且该次健康红唇女郎判定符合继任条件，否则拒绝这份具体动作。重复、越界及稀疏数组也拒绝。

角色变化携带 `registeredRecluseSeat`，见证记录唯一的 `scarlet_woman_d1_11` 或 `scarlet_woman_n2_11` 等判定编号、隐士座位及 `Imp` 注册。日夜查询提供 `currentRoles`、`currentAlignments` 和 `currentAlive`，页面可展示两个实际存活小恶魔。重放从初始角色袋重新计算，不接受缺失、重复、错阶段、错座位、伪造角色或与行动不符的继任注册，也核对提供的存活表。

工作区保持 schemaVersion 2；用户保存事件和前提，刷新后重新搜索隐藏行动，不保存或确认一份可能见证为真实历史。

## 验证与后续

独立 Python oracle 不导入应用实现。矩阵覆盖白天处决/猎手、四/五/十二存活、双方中毒、投毒者自毒、僧侣保护、独立注册、多恶魔白天终局及观察分支；2026-10-03 扩展多恶魔夜间时序、传位竞争和后续信息历史。具体场景和审计见 [V1 验收](../v1-acceptance.md)。下一步继续扩展剩余 22 角色交互矩阵、复杂公开事件顺序、事实来源解释与修订后重放，性能工作暂缓。
