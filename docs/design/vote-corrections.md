# 投票纠正、发生顺序与修订隔离

更新：2026-10-03。本增量完善记录修订，不新增角色能力或性能基准。

## 用户行为

魔典“记录”中的有效投票新增“纠正投票”。选择实际举手玩家，未选表示零票；取消不会改变记录。保存后保留原文及旧举手名单，追加撤回与替代记录，并要求重新核对本日完整性。其他阶段的完整性确认保留。

纠正保持这次投票的原提名、阶段、可见范围及发生位置。新记录的修订号晚于当天后续行动，但推理在原投票位置重放。例如 9 人存活时误录为 5 票，之后猎手击杀隐士、当天无人被处决：旧记录冲突；纠正为实际 4 票并重新确认 D1 完整后，记录可以兼容。较晚保存的纠正不会变成“猎手击杀之后才计票”。

新记录提供“回看原投票”，显示原文、原举手名单和原投票与更正的关系。重复纠正沿完整关系链保持最初发生位置，撤回替代记录不会复活已撤回的原投票。纠正不能改变提名目标、移动阶段或把真实交错投票改为已支持顺序。

## 旧分支保护

原先高级工作区的追加与撤回会直接将旧分支推进到最新修订，混入尚未纳入该分支的记录。现在所有事件追加与撤回都先检查当前分支是否处于最新修订；魔典与高级入口统一要求显式“更新到最新记录”后才可编辑。

旧分支仍可查询及调整本分支的假设，保持其原来的事件、投票和结论条件。投票纠正分支不更新其他分支的修订；用户显式更新旧分支后才看到新的纠正。记录、分支、前提或命题变化后，已有结论仍按工作区快照失效。

## 格式与数据边界

未使用投票纠正的旧工作区仍使用 schemaVersion 2，可以原样读取。第一次保存实质性的投票纠正时，工作区升级为 schemaVersion 3；替代投票使用 `correctsEventId` 指向被撤回的上一份投票。新版继续读取 2 和 3。旧程序会拒绝 3，避免忽略纠正关系而生成不同顺序的结论。

公开导出中存在公开投票纠正时，公开记录格式升级为 schemaVersion 2，保留公开原记录、撤回和替代关系。仅纠正私密投票不会改变公开导出的内容或格式；假设、私密原文、私密投票 ID 与纠正关系均不进入公开导出。私密全量导出、IndexedDB 与离线恢复保留完整历史。

导入验证要求纠正仅用于投票，引用较早且已撤回的投票，保持同一提名、目标、阶段及可见范围，并拒绝缺失、自指、错类型、错阶段、改变可见范围和同一原记录的多个有效替代。旧格式中夹带纠正关系也被拒绝。受损导入不会替换当前工作区。

## 重放与验证

原始事件数组按录入修订保持不变。准备观察查询时，仅将有效替代投票放回其最初投票的相对位置，再按已有日夜模型重放。旧分支只使用其修订以内的事件和历史关系，不读取未来替代记录。规则版本仍为首夜 v4、显式时间线 v7、观察时间线 v8、oracle v6。

19 项修订专项覆盖旧分支写入保护、取消与无变化保存、重复及零票纠正、撤回后不复活、阶段重新确认、旧分支的五票与新分支的四票、存活票与后续遗言票、保留真实交错顺序、公开隐私和受损格式。真实 Z3 查询的兼容见证同时经 TypeScript 与独立 Python 重放。

桌面及手机流程验证“冲突 → 纠正投票 → 阶段尚未确认时停止推理 → 重新确认 → 兼容见证”，以及旧分支对照、显式更新、公开与私密导出、拒绝损坏导入和断网恢复。完整结果及复现命令见 [V1 验收](../v1-acceptance.md)。

当前只支持纠正投票的举手名单，不是通用行动编辑或顺序重排器。提名至计票之间真实插入公开行动仍明确提示未支持；完整 22 角色交互、其他事件纠正和事实来源级解释继续按计划推进。性能优化与测量仍暂缓。
