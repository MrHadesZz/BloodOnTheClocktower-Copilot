# 固定背景的阶段冲突定位

2026-10-07 增量。此功能沿完整日夜记录检查兼容性，定位冲突首次被确认的阶段边界，并回看该阶段来源。它复用现有 Z3 和具体时间线重放，不增加角色规则或改变规则版本。

## 用户入口

- 魔典 → **记录** → **核对固定事实与阶段冲突** → **核对固定事实**。
- 一键分析返回“对局事件或手动前提有冲突”时，在结果中直接核对。
- 前提冲突定位返回“固定事实本身冲突”时，使用同一个核对面板。

默认保留当前分支采纳的手动前提。取消“保留当前分支的手动前提”后，仅检查固定事件；该选择是本次临时诊断参数，不修改保存的假设、分支或事件。只查事件得到兼容见证时，原分析的冲突仍可能涉及手动前提。

v0.4.0可在死亡、处决、提名、投票或猎手的来源中点击[试查单处误录](./record-analysis.md)，查看单字段替代的兼容见证并返回原记录核对。阶段定位本身仍按完整前缀检查；候选试查不等于任意事实的最小冲突集，不修改保存的记录。

## 证据与边界

先检查完整历史。如果找到可重放见证，显示“固定背景已有兼容解释”，无需再枚举每个前缀。否则按 N1、D1、N2、D2 顺序检查完整阶段的历史前缀；保留前缀内所有行动、死亡与阶段完整性观察，不能删除某条死亡或解除某个阶段的封闭来制造兼容世界。

初始真实角色、所见 token 与首夜投毒等保留前提在每次检查中一致。N2 等后续报告只在其夜晚及之后加入，阶段角色条件只在对应阶段及之后加入。查询固定为初始命题，仅用存在的支持或反例见证证明背景可满足；命题的“不可能”不等于背景矛盾。

- **最早确认冲突的阶段**：本阶段前缀确认不一致，且每个更早前缀均有兼容见证。结果展示此前最近的兼容见证和本阶段来源。
- **已确认截至某阶段的记录冲突，最早边界尚未验证**：已经确认一个冲突前缀，但更早阶段存在未知，或预算不足。不能称为最早边界。
- **固定背景已有兼容解释**：至少存在一种合法解释，不能证明全部记录真实，也不表示原来的全部玩家声称成立。
- **请先补齐或核对阶段记录**：准备层发现未封闭阶段、重复事件或尚未支持的公开交错顺序。本次不进入搜索，也不将未支持输入称为规则冲突。
- **阶段定位未完成**：没有已确认的冲突证据，或设置本身的矛盾需要前提定位。未知不作为“不可能”证据。

来源列表包含所定位阶段参与检查的原始事件和已采纳报告，并标注可见性、修订及原文。投票纠正仍按原发生位置重放，来源指向有效纠正记录，保留原投票原文。列表是核对入口，不是来源级最小冲突集；较早的误录与本阶段正确记录也可能一起形成矛盾，不能据此归责玩家或自动删除事件。

## 预算、修订与私密视角

默认总预算 30 秒、40 次检查，单次检查最多 5 秒；Worker 外部时限另留 5 秒。进度保存已经确认的阶段证据，取消和外部超时保留已有结果。更改工作区、关闭面板或卸载组件会终止 Worker，晚到结果不会覆盖新记录；重新打开或刷新后需重新核对。

诊断绑定活动分支的 `baseRevision` 与当前私密座位。旧修订不自动纳入后续记录，其他座位的私密事件不进入来源或求解。更换“保留手动前提”选项后，旧诊断清除。不同规则版本的证据不合并。阶段定位本身不引入新持久化字段，当前客户端读取 schemaVersion 2/3/4；死亡/处决纠正使用格式 4，见[事实纠正说明](./fact-corrections.md)。

## 验证

新增测试验证独立“死者不能再次死亡”前缀参照、真实 Z3 与前一阶段见证重放、后续报告/阶段角色条件的时点、手动前提与只查事件的区别、未知保护、预算证据保留、规则版本变化、失败检查、未封闭阶段、旧修订/私密视角和原位置投票纠正。Worker 测试覆盖进度、终止和超时。桌面及手机浏览器流程覆盖来源、见证、诊断前后私密导出完全一致、结果失效、离线恢复与一键分析入口。

本轮没有进行 Worker 性能优化或基准测量，也未增加新的角色机制矩阵；手机验证为 390px 视口，不替代真机测试。
