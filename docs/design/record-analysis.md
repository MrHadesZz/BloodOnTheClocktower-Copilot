# 单处误录试查

2026-10-08 / v0.4.0。在固定背景阶段核对的具体来源中，检查一处玩家字段或举手名单误录是否存在兼容替代。它补充来源级的条件对照，不生成任意事实的最小冲突集，也不自动纠正记录。

## 从来源到手动核对

运行“一键分析→核对固定事实”，展开冲突阶段的原记录，点击“试查单处误录”。原完整背景先确认冲突；随后只展示有兼容见证的替代候选。展开见证可查看真实角色分配和具体隐藏行动，再点击“前往原记录核对”，聚焦原记录并使用已有纠正入口。

例如D1记录3号处决死亡，N2又把3号记为死亡。试查N2这条来源时，“死亡玩家3号→4号”可能有兼容见证。它说明替代条件可以成立，不说明4号实际死亡。其他玩家也可能形成候选，各有一份合法解释，隐藏机制没有穷举。手动核对后保存纠正，仍需重新确认阶段完整。

| 原记录 | 本次逐个检查的单处替代 | 保持的约束 |
| --- | --- | --- |
| 死亡、处决 | 替换玩家座位 | 类型、发生阶段、其余全部完整观察 |
| 提名 | 分别替换提名人或被提名人 | 原位置；关联投票保持名单和各自可见性，并重新关联 |
| 猎手 | 分别替换行动玩家或目标 | 原位置；死亡、处决及其他行动不随之改写 |
| 投票 | 增删一名举手玩家 | 原提名、原投票位置和其他举手玩家 |

同时改两个字段、改变时间/可见性/类型、添加或删除整条事件、联合修改多条来源，以及胜负、角色声称和能力报告均不属于本次候选范围。报告和角色条件可继续使用已有前提/声称分析。

## 不通过删事件放宽事实

阶段完整性表示已收齐行动与死亡。直接删一条死亡而保留“完整”确认，会把不采信该记录变成“本阶段没有这次死亡”；删提名还可能造成投票失去引用，或改变公开顺序。

因此每个试查候选明确提供一个替代玩家/名单，沿用审计式纠正，在内存快照上重新确认同一阶段。查询仍包含完整的日夜序列、其余死亡、行动、处决、胜负、报告前提和角色条件。不会删除来源、跳过阶段或制造空阶段。提名与计票之间的公开行动交错仍返回未支持。

候选快照及追加事件只用于临时求解，不交给工作区保存回调。浏览器显示原修订与来源，试查前后的私密全量导出、公开导出及本地记录完全相同。

## 修订、视角和预算

来源必须在活动分支的`baseRevision`下有效可见。快照截断后补事件，移除不属于该修订的未采纳报告前提；若活动前提引用未来来源则明确拒绝，不偷偷删除已采纳条件。旧分支可以试查原来源，但写入纠正仍需显式更新到最新记录。连续纠正从当前有效替代开始，沿原引用链保留物理顺序。

默认保留活动分支手动前提，跟随阶段核对的选项；玩家声称不会自动当作真实身份或准确信息。默认引擎预算20秒、最多40次检查、每次最多3秒、最多展示4个候选；Worker总时限25秒。预算和取消保留实时显示的已验证候选，尚未检查或未知项不能用来排除误录可能。

原背景已有见证时不猜测误录；原背景未知或不完整时不展示冲突结论。全部单处替代明确冲突且没有见证时，只表示这个有限范围没有找到替代，不证明原记录正确。规则版本变化立即停止组合证据，并保留此前的结果。

更换来源、修改记录/前提/分支/视角、改变是否保留前提，或关闭面板都会取消对应运行并移除旧结果。明确取消当前试查时，已有候选保留。私密原文只在当前可见视角展示；试查结果不进入公开导出。

## 验证与限制

21项核心专项覆盖五类真实Z3冲突及候选见证、TypeScript和独立Python重放，旧修订、连续纠正、私密导出、未知、预算与规则变化。新增3项Worker生命周期回归和10项桌面/390px浏览器流程，覆盖见证展开、前往原记录、导出不变、人工纠正再分析、旧分支只读、预算证据保留、取消及断网恢复。

角色规则哈希、工作区2/3/4/5及公开导出1/2/3/4均沿用此前范围。本功能没有新增角色机制或任意投票中断；手机视口不等于真机，完整V1仍未完成。详细结果见[验收记录](../v1-acceptance.md)。
