# 死亡与处决记录的追加式纠正

2026-10-08 / v0.2.0 增量。支持纠正同一发生阶段的死亡、处决玩家座位。沿用追加记录的审计方式，不覆盖原文，不修改角色规则。

## 操作闭环

1. 一键分析或条件推理发现背景冲突后，运行阶段核对，展开本阶段的来源。
2. 点击 **在记录中核对…**，打开记录面板并聚焦对应原记录。也可直接进入“记录”。
3. 点击 **纠正死亡** 或 **纠正处决**，核对原文，选择实际玩家并保存。取消或保存相同座位都不改变事件。
4. 该阶段重新开放，确认真实行动和死亡收齐后，重新点击 **本阶段记录完整**。
5. 再次分析；有兼容见证才说明当前条件可以成立，未知结果继续保持未知。

例如 D1 已记录 3 号处决死亡，N2 又误把 3 号记为死亡。阶段定位可确认 N2 边界；将 N2 死亡纠正为 4 号、重新确认 N2 后，示例可以找到兼容见证。纠正入口不自动认定哪个座位正确。

处决与死亡是两条独立记录。纠正处决不会同时修改死亡，纠正死亡也不会修改处决；若两条都误录，需分别核对。当前不支持在纠正表单中改变记录类型、发生阶段或可见性；误录到其他阶段时可使用已有撤回及新增记录流程。

## 来源、顺序与修订

`correctStandardFact` 要求最新编辑修订及当前可见、有效的死亡/处决来源，验证新座位并追加原记录的撤回及关联替代。替代保留原发生阶段、可见性和 `correctsEventId`；连续纠正引用上一份有效替代。重放通过沿引用链取得原位置，不把后来追加的纠正当作后来发生的行动。

更早的原文和每次中间替代均保留在记录历史。固定事实阶段核对引用有效替代，仍能回看纠正前原文。旧分支的 `baseRevision` 与采纳前提保持原样，仍可查询旧观察；在旧分支写入前必须先显式更新。不存在、已撤回、其他座位私密来源和无效引用均被拒绝。

保存后只重新开放对应阶段，其他阶段的完整性确认保留。已打开的纠正表单绑定工作区快照；记录、前提或录入阶段变化后，保存按钮失效，需重新打开。来源跳转会聚焦记录并保留 1–10 天的魔典阶段选择范围。

## 格式兼容与公开导出

| 场景 | 工作区格式 | 公开导出格式 |
| --- | --- | --- |
| 原有记录，无纠正 | 2 | 1 |
| 仅使用投票纠正 | 3 | 含公开投票纠正时为 2 |
| 使用死亡/处决纠正 | 4 | 含公开死亡/处决纠正时为 3 |

v0.2.0客户端读取2/3/4工作区；v0.3.0进一步支持[行动纠正的格式5](./action-corrections.md)。只使用死亡/处决纠正时仍为格式4；随后再纠正投票不会降回3，已升级的格式5也不降级。旧格式中夹带不支持的纠正会被拒绝，不能通过修改版本号伪装兼容。

公开导出的格式只由公开事件决定，私密纠正及私密阶段再确认不会改变公开导出内容或格式。导入验证检查来源存在、类型一致、原记录已撤回、相同阶段和可见性、单一有效替代及合法座位；受损文件不能替换现有工作区。

## 验证范围

新增 22 项单元回归覆盖真实 Z3 冲突与纠正后兼容、TypeScript 和独立 Python 见证重放、重复纠正、原位置、旧分支、类型/座位/引用拒绝、格式不降级及公开脱敏。新增 7 项浏览器流程覆盖桌面和 390px 手机的来源聚焦、取消/保存、重新确认、再次分析、旧分支只读、全量导出与离线恢复、私密纠正、受损导入及过期表单。

本功能不生成最小事实来源冲突集，不改变角色模型、查询预算或未知保护；当前仍是有限模型的实验性版本。
