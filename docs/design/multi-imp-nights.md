# 多个小恶魔的夜晚

更新：2026-10-03。适用于标准 7–15 人 Trouble Brewing 的已声明有限模型，延续[隐士与红唇女郎](./recluse-scarlet.md)及[实际阵营、自毒](./alignment-and-self-poison.md)的约束。性能优化与基准测量继续暂缓。

## 规则依据与模型选择

[官方术语表](https://wiki.bloodontheclocktower.com/Glossary)说明，多个恶魔在场时，每个存活恶魔都属于能力中的“恶魔”。[小恶魔](https://wiki.bloodontheclocktower.com/Imp)每个非首夜选择一个目标，自杀传位产生的新小恶魔当夜不再行动。[能力规则](https://wiki.bloodontheclocktower.com/Abilities)说明，死亡立即失去能力，来源死亡或变身立即结束持续效果。[红唇女郎](https://wiki.bloodontheclocktower.com/Scarlet_Woman)在每次恶魔死亡前检查五人阈值，符合条件时优先继任。通常的善良胜利需要所有恶魔死亡，包含善良恶魔，依据[麻脸巫婆页的通用说明](https://wiki.bloodontheclocktower.com/Pit-Hag)，本项目没有实现麻脸巫婆。

本模型把所有夜晚开始时存活的小恶魔排列为依次行动的队列，观察搜索枚举所有先后顺序；具体见证保存其中一组顺序。新继任者本夜不进入队列。守鸦人在其死亡时固定信息；送葬者、共情者和占卜师在各自后续信息步骤处理。守鸦人原先使用夜末状态的错误已在[信息时点增量](./information-timing.md)修复。这是结合各能力与既有夜晚步骤的有限组合推导，不作为任意剧本或说书人时序的通用裁定。

## 每次攻击的结算

1. 核对行动者。每个夜晚开始时的存活小恶魔出现恰好一次；不能加入新继任者、已死者或其他角色。单恶魔旧字段继续有效，与队列字段混用会被拒绝。
2. 行动前已死亡则记录 `skipReason: "dead"`；对局已经结束则记录 `"game_over"`。两种情况都不能再提供目标、镇长转移或继任选择。中毒小恶魔仍选择目标，其能力无效果，不能当作跳过行动。
3. 按本次状态结算镇长转移、僧侣与士兵保护。攻击同一个目标两次不会造成两次死亡，也不补发一次攻击。选择死者仍然合法。
4. 每次实际死亡检查红唇女郎与自杀传位。只有行动的小恶魔直接选择并杀死自己，才触发普通爪牙传位；镇长把死亡转移给行动者不等同于主动自杀。已变成小恶魔的原爪牙不能再次作为另一次传位的候选。
5. 投毒者死亡或接任为小恶魔时，立刻清除毒效，后续小恶魔或士兵可以恢复能力。僧侣死亡时，立刻撤销本次保护，后续攻击可能杀死原保护目标。僧侣在其选择步骤中毒时不产生有效保护，本模型不会因为其稍后恢复健康而补发保护。
6. 先检查是否还有实际存活的小恶魔，再检查剩余人数。杀死其中一个不直接判善良胜利；最后一个死亡且没有继任者则善良胜利。存活恶魔仍在且只剩两人，则邪恶胜利，剩余队列跳过。

角色变化不修改实际阵营。`roleChanges.sourceImpSeat` 记录触发继任的攻击来源，`impSteps` 记录实际执行或跳过及死亡结果。来源效果在每一步更新，不能等到整夜结束后才清理。

## 行动与见证格式

```json
{
  "cycle": 2,
  "poisonerTarget": 10,
  "monkTarget": 2,
  "butlerMasterSeat": 1,
  "impActions": [
    { "actor": 11, "target": 12 },
    { "actor": 12, "skipReason": "dead" }
  ]
}
```

每次攻击可独立提供 `mayorRedirectTarget`、`impSuccessorSeat` 或 `scarletRecluseRegistration`。隐士接任的爪牙注册在单恶魔见证继续使用 `imp_successor_n<cycle>`；多个攻击时增加来源座位，使用 `imp_successor_n<cycle>_<actor>`。红唇女郎的独立隐士恶魔注册继续使用 `scarlet_woman_<phase>_<observer>`。证据核对唯一性、具体座位、合法注册角色和完整行动队列，拒绝额外伪造记录。

观察阶段仍记录死亡集合，记录的排列不决定隐藏攻击顺序。查询搜索合法顺序、各自目标及传位；界面显示的是一组可能隐藏行动。工作区继续使用 schemaVersion 2，保存公开事件和采纳前提，刷新后重新生成见证。

## 搜索边界与验证

每个排队小恶魔至多产生一次死亡，新继任者不会增加本夜攻击，因此超出队列人数的死亡集合可以排除。在本 TB 切片中角色只会变成小恶魔，已经成为小恶魔的角色不会因死亡变回原角色，可排除要求其随后变成其他角色的查询分支。其余搜索仍受原有时间、设置候选与行动上限约束，未穷尽时保留未知及具体原因。

独立 Python oracle 不读取应用实现。矩阵覆盖 12/15 人的两种先后顺序、独立/重复目标、互杀和跳过、毒效/保护变化、镇长转移、爪牙竞争与信息步骤；完整历史包括 15 人两位旧恶魔同时传位，下一夜两位新恶魔杀死守鸦人与贞洁者，同时核对守鸦人、占卜师和共情者信息。TypeScript 和 Python 同时审计正常见证以及遗漏、重复、错误行动者、篡改目标、伪造跳过与额外注册。

仍未证明全部 22 角色的任意动态组合、任意输入损坏、任意更长历史或通用醉毒循环。规则版本、具体测试数与复现命令见 [V1 验收](../v1-acceptance.md)。
