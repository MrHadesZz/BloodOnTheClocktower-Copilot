# 待开发方向

以下是邀请讨论的方向，不是已经完成的功能或交付承诺。当前能力和限制以 [覆盖审计](./v1-coverage.md) 与 [验收记录](./v1-acceptance.md) 为准。

| 方向 | 可以先做的工作 | 验证重点 |
| --- | --- | --- |
| 新手上手 | 首次使用引导、匿名示例对局、录入帮助 | 能顺利记录一条信息并理解条件结果 |
| 手机与可访问性 | 操作目标、长记录浏览、键盘导航、读屏名称 | 390px 布局与实际手机体验 |
| 规则与反例 | 已声明暗流涌动模型中的交叉场景、信息时点和逐次注册反例 | TypeScript 和独立 Python 对照；保持未知边界 |
| 推理解释 | 更易读的多条件解释、固定事实的来源定位 | 每份解释仍可回看来源并重放验证 |
| 复盘与分享 | 匿名复盘、公开导出的说明与可读呈现 | 不泄露私密视角、隐藏身份和私人记录 |
| 性能 | Worker 初始化、复杂历史的预算与取消、真机测量 | 区分冷启动、查询与记录提交耗时 |
| 更多剧本 | 讨论可扩展规则表示和角色能力接口 | 先补齐当前 TB 模型与验收；新剧本尚未实现 |
| 自然语言录入 | 输入转为可编辑的结构化草稿 | 后续阶段讨论；需要确认、隐私与独立规则校验 |

想参与可从 Issue 提案开始：描述谁会用、在哪一步遇到问题、预期怎样操作，并提供匿名样例。规则讨论请附官方来源，明确哪些部分是模型推导。新增功能不改变本项目的非商业、署名和水印许可要求。

## 当前开发优先级（2026-10-08）

1. **推理解释与记录核对**：已有[阶段定位](./design/fact-history.md)、[审计式纠正](./design/action-corrections.md)和[单处误录试查](./design/record-analysis.md)。可从具体来源查看替代条件与兼容见证，再手动核对原文。下一步扩展多条来源的联合核对及更易读的原因对照；单字段候选不等于固定事实的最小冲突集，放宽观察需保留正确的完整性语义。
2. **现有暗流涌动模型的交叉反例**：继续验证醉毒持续、角色变化、公开事件顺序、终局及更长历史，保持超时与未支持交互的未知结果。
3. **新手与手机录入**：围绕记录、完整性确认、条件和见证设计匿名示例及操作引导，并补充键盘和真机体验验证。
4. 性能优化及测量继续暂缓，保留历史基线；现有规则与验收门槛满足后再推进更多剧本及自然语言录入。
