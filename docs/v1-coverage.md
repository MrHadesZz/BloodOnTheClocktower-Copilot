# V1 规则与发布覆盖审计

更新日期：2026-10-08 / v0.4.0。线上试用地址是 [clocktower-copilot-ten.vercel.app](https://clocktower-copilot-ten.vercel.app)。Vercel 将项目首次部署自动分配到了生产域名；**这个部署仍是开发中版本，不代表完整 V1 验收通过**。本轮准备 GitHub 源码及构建包发布，线上试用的部署版本可能不同。

规则层用 Z3 约束 7–15 人的初始角色、所见 token 与采纳的首夜报告；跨阶段部分在 Z3 候选之上枚举隐藏行动，再做具体时间线重放。工作区只把明确封闭的死亡和白天行动当作完整观察。搜索耗尽时间、候选或行动预算时返回 `unknown`，不把未搜索的世界排除。见证包含初始分配、红鲱鱼、逐次注册和可重放行动历史。

## 冲突定位与纠错增量（2026-09-27）

- 魔典查询冲突后可以定位互不兼容的采纳前提，回看原始报告及固定事实；仅在核心仍冲突且每项删除均有有效见证时标记“已验证最小前提冲突集”。最小是相对于固定事实的不可再删，不保证条数最少、唯一原因或自动判定谁说谎。
- 超过检查/时间预算、规则未支持或无有效见证时，返回未完成状态。Worker 持续保存已确认核心，即使单次求解超过外部时限也保留部分解释；初始化或初始检查未确认冲突时不会编造核心。取消、关闭弹层或更改前提会终止旧定位。
- 支持在新分支试取消单个前提，保留原分支的修订、其他前提与所有记录，自动重新查询并展示对照；新分支仍冲突或结果未知时明确提示。分支可本地恢复，解释与对照在关闭面板或刷新后需重新生成。
- 验收：121 项单元测试、生产构建与本地生产预览的 18 项 Chromium 浏览器测试通过。覆盖桌面 1440×1000、手机 390×844、来源回看、删除见证、分支对照与恢复、部分预算、混合报告、取消/关闭/版本失效，以及断网后的冲突定位和纠错查询。未部署或重新验收线上站点。
- 本轮新增独立有限角色排列对照、真实 Z3 删除见证重放、未知/预算/混合规则版本、私密视角、分支隔离及 Worker 超时/取消测试；不代表完整 22 角色动态交互矩阵已经覆盖。

## 一键声称与多人组合增量（2026-09-30）

- 自动在当前私密视角与修订下临时检验声称，先确认固定背景可满足，再定位玩家条件冲突；不会把记录永久提升为真值，也不修改已保存分支前提。
- 除单人放宽外，已接入利用确认冲突的多人组合搜索。组合必须携带兼容见证，逐人恢复条件均确认冲突后才称不可再缩小。未知和预算耗尽不作为冲突、最小性或枚举完成的证据。
- 组合界面展示声称与见证角色对照、具体报告来源、酒鬼所见 token 和见证中的投毒行动。展示的是可能解释，仍无法直接确认玩家撒谎，也不保证全局人数最少。
- 默认最多 6 组、30 秒，提供实时进度和证据保留。Worker 终止后忽略晚到进度，旧修订结果不会覆盖新记录。私密视角、背景事实和手动前提在所有组合中保持一致。
- 新增独立穷举子集对照、真实 Z3 见证具体重放、未知恢复检查、组合上限、缓存预算边界、进度快照和取消回归。角色规则核心未扩展；完整动态交互矩阵与性能验收仍待完成。
- 验收：146 项单元测试、生产构建与本地生产预览 30 项 Chromium 浏览器测试通过；包含桌面 1440×1000、手机 390×844、多人组合及来源、单人回退、展示上限、取消、修改记录后的旧结果失效、前提保留和断网恢复。使用项目现有 Playwright 流程，Browser 插件当前不可用。未重新部署线上版本。


## 细粒度条件解释增量（2026-09-30）

- 每个经验证的玩家放宽组合增加“细查原因”，把开局身份、每份报告的准确转述、当夜能力有效分别作为临时条件，寻找有兼容见证的具体解释。保留其他玩家、当前修订、私密视角、全部已采纳手动前提和固定事件。
- 复用多人组合的已确认冲突搜索和逐项恢复验证。兼容、不可再缩小及枚举完成分别验证；未知、混合规则版本、上限和预算都不作为否定或最小性证据。默认 20 秒、最多 6 份解释，Worker 外部时限多留 5 秒，取消和超时保留已确认结果，关闭面板或记录变化后终止旧请求。
- 解释明确列出座位、N1/N2 等夜晚、原报告、放宽和仍保留的条件。同一报告可比较只放宽准确转述与只放宽能力有效的不同方案。具体醉酒、中毒或角色不符说明从兼容见证及信息时点的具体重放派生；仅取消能力有效前提不证明其失效，见证未支持原因时明确说明。投毒源夜死后的效果终止不会被目标字段误报为中毒。
- 完成独立 64 子集对照、真实 Z3 首夜与跨夜见证重放、酒鬼所见身份、明确投毒、N2 单独定位并保留 N1、手动前提不被放宽、视角与修订隔离、未知恢复检查、规则版本不一致、上限和 Worker 超时/取消测试。
- 本轮验收：159 项单元测试、生产构建和本地生产预览 36 项 Chromium 浏览器测试通过；新增 6 项浏览器测试覆盖桌面 1440×1000、手机 390×844、原报告与保留条件、醉酒/中毒证据、跨夜、离线重载、取消、关闭及旧结果失效。Windows 本机预览返回 HTTP 200。未重新部署线上版本。
- 这一增量完成条件层的细分，不枚举每组条件的所有隐藏世界，也不最小化固定行动事实来源；22 角色规则语义、完整交互矩阵、跨天记录历史和密集日志性能验收仍继续按计划推进。

## 跨天录入与阶段角色增量（2026-09-30）

- 记录按 N1、D1、N2、D2 分组，支持显式核对完整、前往下一阶段与选定阶段恢复。补录或撤销行动与死亡使同阶段确认失效，其他阶段及旧分支版本保留；报告与补记胜负不改变观察完整性。缺少阶段时指出所缺阶段及记录入口，阶段完整只约束行动和死亡。
- 声称新增可选的纠正/改口关联及身份时点，旧 schemaVersion 2 工作区可继续读取，无需迁移。纠正保留原文、撤回误录，并只取消编辑分支对原报告的采纳；改口保留历史与手动前提，一键分析采用最新有效声明。传递关系避免撤回中间声明后重新采纳更早的报告；修订与私密视角继续限制来源和编辑。
- 新增精确阶段结束时的角色条件，与初始角色事实分别处理。在隐藏行动搜索和独立具体重放中都检查对应阶段，而不是将当前角色当成初始身份。真实 Z3 用例验证“红唇女郎开局、N2继任小恶魔”可以兼容，以及只放宽错误的 N2 当前角色条件仍保留正确开局身份；范围外或未确认阶段返回未知/明确拒绝，不跳过约束。
- 本轮验收：175 项单元测试（18 个文件）、生产构建、42 项本地 Chromium 浏览器用例获得通过结果。全量浏览器运行 40 项通过，另 2 项改口/纠正用例修正测试定位歧义后分别复测通过；应用代码未因测试定位修改。新增 16 项单元和 6 项浏览器用例，包括来源关系、分支隔离、公开导出、格式拒绝、精确阶段约束和见证重放、连续录入、桌面/手机、离线恢复与重新确认。Windows 本机预览 HTTP 200，截图和横向溢出检查通过。
- 本机生产预览已更新，未重新部署线上版本。此增量完成跨天录入和历史交互，不构成全部 22 角色交互或 10/12/15 人多夜性能验收；设计包 13 项 Python 参考测试此前通过，本轮没有重复运行。

## 独立规则与性能增量（2026-09-30）

- 新增不读取应用实现的 Python oracle，488 个有限输入（首夜 115、夜晚 311、白天 62）与真实 Z3/TypeScript 对照；其中 27 个查询独立穷举 48 个合法角色补全。另验证注册证据篡改拒绝和隐士继任的未知保护。

- 验收：665 项单元、13 项新 Python 锚点、13 项原设计参考、生产构建及本地生产预览 47 项浏览器回归全部通过；新增桌面/手机注册、10/12/15 人 N3 密集日志取消与离线恢复检查。

## 阵营、自毒与具体注册增量（2026-10-01）

- 日夜状态把实际阵营与真实角色分开；健康隐士通过爪牙注册成为善良小恶魔。共情者使用实际阵营，占卜师检测恶魔角色，终局仍按恶魔存活和人数判断。证据显示实际阵营，并跨实现拒绝伪造、缺项与重复注册。
- 标准路径允许单投毒者自毒；持续到黄昏，来源死亡或变身提前结束。自毒不阻止其他健康角色让其取得新角色。该持续语义是有官方依据的有限模型推导，不声称为通用醉毒循环裁定；见 [机制说明](./design/alignment-and-self-poison.md)。
- 独立矩阵扩至 520 个输入（首夜 139、夜晚 311、白天 62、观察历史 8）。后续共情者/占卜师逐条检查提供的具体注册，并接受同一信息的不同合法注册组合。
- 验收：709 项单元、16 项 Python 锚点、13 项原设计参考、生产构建及 51 项浏览器回归通过；最终校验收紧后复测 9 项相关流程通过。新增四项桌面/手机、善良恶魔、离线恢复、自毒 What-if、保存与导入回归，截图已检查，无新增浏览器错误。
- 最终性能专项 36 项通过，Node 90 次、浏览器 108 次正常查询未知率 0%，396 份见证经独立审计；9 项低预算边界返回未知。单格样本 P95：Node 51.7–306.3ms、浏览器冷 Worker 352.4–632.3ms。与前次测量相比存在波动，未做性能优化，也不能由少量样本判断速度趋势。
- 当前版本为首夜 v4、显式时间线 v3、观察时间线 v4，schemaVersion 2 工作区无需迁移。完整 V1、真机性能与线上新版本仍未验收。

## 隐士死亡与红唇女郎继任增量（2026-10-01）

- 白天处决/猎手、单恶魔开始的夜晚攻击造成隐士死亡时，可独立注册为恶魔并触发健康红唇女郎。检查死亡前五人阈值及双方健康状态；猎手注册不强制红唇女郎注册。保留原恶魔、死者真实隐士角色和实际阵营，见证显示两个存活小恶魔。
