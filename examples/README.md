# 匿名教学示例

以下文件是合成七人暗流涌动记录，不含真实玩家数据。示例预先采纳七项已知身份前提，便于稳定复现冲突与兼容见证。

## 死亡记录纠正（v0.2.0）

1. 打开应用，进入 **高级推理 → 导入 JSON → 返回魔典**。
2. 导入 `anonymous-fact-conflict.json` 后点击 **一键分析 → 核对固定事实**，预期定位 N2：D1 已死亡的 3 号再次被记录为 N2 死亡。
3. 展开 N2 来源，点击 **在记录中核对3号死亡**，将实际死亡玩家纠正为 4 号。
4. 重新确认 N2 记录完整，再次分析，预期得到兼容见证。

`anonymous-fact-corrected.json` 已保存纠正和原文。它采用工作区格式 4，并保留旧分支；切换回基础记录仍能检查原来的冲突。旧文件使用格式 2，新客户端可直接读取。

## 提名与投票关联纠正（v0.3.0）

1. 导入 `anonymous-nomination-conflict.json`，点击 **一键分析 → 核对固定事实**，预期定位D1：提名与计票针对3号，后续却记录4号处决死亡。
2. 展开来源，点击 **在记录中核对2号提名3号 → 纠正提名**，选择实际被提名人为4号。
3. 核对表单中的1/2/3/4号举手名单，勾选关联投票确认后保存。提名和投票都有审计替代，原文和顺序保留。
4. 重新确认D1，再次分析预期得到兼容见证。

`anonymous-nomination-corrected.json`采用工作区格式5，已经保存上述纠正和阶段再确认；旧分支保留原冲突。公开提名和投票均可查看，七项角色前提仅作为教学条件，不代表实际玩家的隐藏身份已被推断。

这些结果在发布准备时经过真实Z3验证；提名纠正后的见证另外通过TypeScript及独立Python重放。兼容见证是条件解释，不用于认定玩家诚实或撒谎。
